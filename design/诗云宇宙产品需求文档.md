# 诗云宇宙产品需求文档

> 文档状态：需求基线  
> 当前阶段：H5 原型验证 / 诗云 2.0 储备功能  
> 更新日期：2026-07-30  
> 适用范围：微信小程序、微信 H5、诗云公共诗词库、拓扑接口、埋点与运营配置

## 1. 文档目的

本文档汇总诗云宇宙从概念提出至当前原型验证阶段已经确认的业务要求、视觉原则、交互流程、数据方案、接口边界、性能目标和验收标准。

本文档是后续产品、设计、前端、服务端、测试和素材制作共同使用的需求基线。若后续实现与本文档冲突，以最新经过确认的需求变更为准，并同步更新本文档。

## 2. 一句话定义

诗云宇宙是诗云首次进入时的沉浸式品牌体验：用户化作一束正在飞行的诗光，在一镜到底的宇宙旅程中依次看见唐朝星团、盛唐诗人群星和李白作品星系，最终整个宇宙坍缩为一个奇点，在光影中融化并过渡到常规创作首页。

## 3. 产品背景与理念

“诗云”概念受到刘慈欣小说中“诗云”意象的启发，但产品不复刻小说情节，也不直接复制受版权保护的文本、画面或角色设定。

诗云宇宙希望表达：

- 中华诗词不是静态书库，而是一片仍在运行的文化宇宙。
- 朝代是星团，诗人是恒星，作品是围绕诗人运行的星体。
- 每一首诗与诗人、时代、意象之间都存在千丝万缕的联系。
- 用户不是站在宇宙之外浏览目录，而是化作一束诗光进入其中。
- 宇宙最终坍缩到用户的创作首页，表达“千年诗光汇入此刻，由你继续写下”。

诗云宇宙既是品牌表达，也是中华诗词库的空间化入口。首期以李白为引导路线完成体验验证，后续扩展为可自由探索的完整诗词宇宙。

## 4. 产品目标

### 4.1 核心目标

1. 在首次进入诗云时建立强烈、独特、具有记忆点的品牌认知。
2. 用空间关系解释“朝代—诗人—作品”的诗词知识层级。
3. 通过镜头引导和逐层探索，让用户自然理解诗云宇宙的交互方式。
4. 验证 Three.js/WebGL 在微信 H5 和小程序 WebView 中的视觉上限与性能边界。
5. 为后续接入完整中华诗词库、作者主页和诗文详情提供可扩展的拓扑框架。
6. 动效结束后自然回到常规创作首页，不增加用户进入核心创作功能的心智负担。

### 4.2 非目标

首个可上线版本暂不追求：

- 一次性加载全部诗人和全部诗文。
- 在宇宙内完成复杂检索、编辑或创作流程。
- 强制接入登录态后才能体验。
- 使用背景音乐作为体验成立的前提。
- 在低端设备上保持与高端设备完全相同的粒子量和体积云质量。
- 使用独立向量数据库承载基础浏览拓扑。
- 一比一复制第三方作品的模型、素材、文案或代码。

## 5. 需求优先级

### 5.1 P0：必须满足

- 整段引导使用同一台透视相机，一镜到底，不得突然切换视角。
- 首阶段远处能看见璀璨的唐朝星团。
- 进入唐朝星团后，李白、杜甫、王维等诗人以恒星形式出现。
- 李白必须是诗人层最耀眼、最具识别度的恒星。
- 进入李白星系后，作品围绕李白运行，并形成广域荧光联系网。
- 用户旅行体必须具有高速前进方向感，不能是简单光球套光环。
- 气态星云必须有缓慢流动和空间纵深，不能只是静态背景贴图。
- 各段镜头位置、朝向、滚转、焦点和 FOV 连续变化，不能瞬移。
- 点击作品后可放大查看诗文详情，诗文内容允许异步加载。
- 最终通过奇点坍缩过渡到常规创作首页。
- 首次体验不依赖微信登录。
- 低性能设备必须有可用的降级方案，WebGL 不可用时不能卡死。

### 5.2 P1：应当满足

- 用户在停泊阶段可拖动屏幕 360° 环顾宇宙。
- 航行途中有真实掠过感，附近星体和诗文彗星与运动方向一致。
- 诗文可以附着在彗星尾部或飞行路径中，方向与彗星轨迹一致。
- 星团、诗人和作品使用不同的空间尺度和视觉语言。
- 当前阶段预加载下一阶段资源，减少点击后的等待。
- 支持重新体验诗云宇宙。
- 提供合理的跳过或失败降级入口，但不破坏主视觉。
- 拓扑资源可通过版本号和缓存长期复用。

### 5.3 P2：后续扩展

- 所有朝代星团自由探索。
- 历史上重要诗人全部成为可访问恒星。
- 每个诗人的全部作品形成独立恒星系。
- 诗人、作品、意象、地点、题材和典故形成更多关系线。
- 语义搜索与 RAG 导航，例如“带我去看写月亮的诗”。
- 根据节日、地理位置或运营主题生成专题星云。
- 加入可选音乐、空间音效与触觉反馈。

## 6. 用户与触发规则

### 6.1 目标用户

- 第一次进入诗云、尚未形成产品认知的用户。
- 对诗词文化、传统美学、沉浸式互动或数字艺术感兴趣的用户。
- 未登录游客和已登录用户均可体验。

### 6.2 首次进入规则

已确认方向：

- 诗云宇宙主要用于首次进入体验。
- 首次体验完成后进入常规创作首页。
- 是否完成体验应记录在前端本地存储，不依赖登录。
- 游客后续登录不应重复强制播放。
- 清除本地数据或主动点击“再次进入诗云宇宙”时可以重新播放。

建议实现：

```text
poetryUniverseExperienceVersion = "v1"
poetryUniverseCompleted = true | false
poetryUniverseLastStage = "intro" | "dynasties" | "poets" | "works"
```

体验版本升级且产品希望重新展示时，通过版本号决定是否再次触发，不复用单一布尔值永久屏蔽。

### 6.3 登录要求

- 诗云宇宙入口、拓扑浏览和公共诗文详情均不要求登录。
- 诗云宇宙内不得提前拉起微信登录弹窗。
- 用户进入常规首页后，继续遵循现有游客创作与登录引导逻辑。
- 接口不得把 Access Token 当作公共拓扑查询的必要条件。

## 7. 完整体验流程

```text
进入诗云
  → 诗光苏醒
  → 镜头环绕并交还视角
  → 远望唐朝星团
  → 驶向唐朝星团
  → 进入盛唐诗人恒星群
  → 选择李白
  → 飞向李白恒星系
  → 查看环绕李白的作品星体
  → 选择一首诗并放大查看
  → 宇宙坍缩为奇点
  → 光影融化
  → 显示常规创作首页
```

## 8. 分阶段业务要求

### 8.1 阶段 0：资源加载

目标：尽快显示可感知的品牌画面，不让用户面对空白页或粗糙 Loading。

要求：

- 优先加载品牌 Logo、暗空环境、用户诗光和第一阶段唐朝星团。
- 不等待全部诗人、作品和诗文详情资源加载完成。
- 加载状态应融入宇宙视觉，不使用默认进度条或技术性报错文案。
- 资源加载失败时应提供进入常规首页的降级入口。
- 不显示“轻触开启”这类无品牌辨识度的占位文案。
- 顶部品牌标识使用项目真实 Logo：`miniprogram/assets/images/brand-icon.png`。

### 8.2 阶段 1：诗光苏醒

目标：让用户理解“自己就是正在进入诗云的那束光”。

视觉：

- 用户形态不是普通球体、星球或套着圆环的光球。
- 当前确认方案为具有明确前进方向的半透明能量水滴/诗光。
- 能看到内部能量流线、贴体光晕和自然粒子尾迹。
- 尾迹至少包含短程离子、长程烟雾和稀疏火花三个层次。
- 禁止使用多条平直 Line 作为主要彗尾。
- 禁止使用低质量、明显重复的透明 PNG 制造塑料感。

镜头：

- 使用第三视角看见用户诗光。
- 镜头缓慢环绕诗光，建立主体和空间关系。
- 环绕结束后允许用户拖动屏幕 360° 环顾。
- 镜头运动要有叙事节奏，不急促、不突然停下。

交互：

- 用户点击明确的主操作按钮后继续航行。
- 主操作按钮需要符合诗云现有金、玉、墨色设计语言。
- 不使用普通矩形按钮或廉价霓虹描边。

### 8.3 阶段 2：远望唐朝星团

目标：在真正飞行前，用户从远处就能识别目的地。

视觉：

- 唐朝不是一颗单独的星，而是一片璀璨的大型星团。
- 远景应能看见明亮核心、旋臂、星尘与金玉双色气态云。
- 唐朝星团应明显比其他朝代更明亮，但仍保留深邃暗空。
- 星团不能像贴在屏幕上的静态云图。
- 星云中高亮区域必须缓慢流动，具有真实三维遮挡和视差。
- 天空盒只承担无限远暗空和遥远恒星，不承担主要气态云。

交互：

- 用户点击按钮后驶向唐朝星团。
- 其他朝代可以以较暗星团形式存在于远处，首期不可进入。
- 用户环顾时不同方向必须出现不同的宇宙内容，不能是单张背景图旋转。

### 8.4 阶段 3：飞向唐朝星团

目标：通过一段完整的空间穿越建立速度、距离和浩瀚感。

镜头：

- 与上一阶段使用同一台相机。
- 起飞第一帧必须继承上一阶段最后一帧的相机位置、焦点、Up 和 FOV。
- 沿连续三维曲线飞行，不允许调用固定机位直接重置。
- 使用轻微侧后方跟拍，既能看到用户诗光的水滴轮廓，也能看到前方目的地。
- 相机不能始终正对尾部，否则旅行体会重新看成圆球。
- 加速、巡航、减速均使用连续缓动。
- 抵达后的停泊机位属于同一条曲线的末端，不是另一个镜头。

环境：

- 前景应有星体或诗文彗星自然掠过，形成视差。
- 彗星头、尾迹和诗文方向必须与速度方向一致。
- 诗文可以出现在彗尾之后，但不能像二维 UI 直接贴在屏幕。
- 不使用覆盖全屏的廉价放射线模拟速度。
- 可在不同航段交叉淡入不同深空环境，但六面图过渡必须连续。
- 动态气态云应作为真实场景对象存在，不随天空盒固定。

节点切换：

- 上一阶段节点先渐隐或缩小。
- 下一阶段节点在飞行中后段逐渐出现。
- 不允许在某一帧突然删除全部旧节点并瞬间显示新节点。

### 8.5 阶段 4：盛唐诗人恒星群

目标：让用户理解“著名诗人是星团中最明亮的恒星”。

视觉：

- 李白、杜甫、王维、白居易、孟浩然等以真实恒星的视觉语言出现。
- 恒星应有程序化表面、克制日冕和光芒，不使用岩石球或发光贴纸。
- 李白是当前空间中最明亮、体积最大、层次最丰富的恒星。
- 唐朝星团的远景核心在相机穿入后必须自动衰减，不能抢过李白亮度。
- 不同诗人可以使用有辨识度的色温，但整体保持金、玉、月白体系。
- 大量未命名小恒星构成盛唐星海，不能只显示五个孤立节点。
- 标签使用 DOM 或高清 SDF 文本，避免中文纹理模糊。

交互：

- 用户可拖动屏幕查看不同方位的诗人。
- 点击李白进入下一阶段。
- 点击暂未开放的诗人时给出轻量提示，不跳转错误页。
- 标签点击热区与恒星位置一致，不能漂移。

### 8.6 阶段 5：飞向李白恒星系

目标：从“诗人是恒星”自然过渡到“一人自成宇宙”。

镜头：

- 继续使用原相机和当前空间坐标。
- 飞行目标是李白主星，但旅行者最终停泊在李白星系外缘，不能与李白主星重叠。
- 停泊后相机焦点仍锁定李白主星。
- 用户诗光保留在近景或侧前景，李白主星保持中心视觉地位。

环境：

- 越靠近李白，诗文星尘和荧光联系逐渐增多。
- 作品轨道不能在点击后瞬间全部出现，应在飞行中后段渐显。
- 李白星系应从远处的一个亮点逐渐展开为多层结构。

### 8.7 阶段 6：李白作品星系

目标：体现作品数量、作品之间的联系以及李白诗歌宇宙的浩瀚。

空间结构：

- 李白是恒星系中心。
- 作品沿多层、不同倾角的轨道围绕李白运动。
- 重点作品拥有名称标签和点击交互。
- 非重点作品可以先作为无标签作品星尘存在。
- 多条细密、弯曲的荧光关系线连接李白与作品、作品与作品。
- 关系线不能全部是机械直线，应具有柔和弯曲和流动脉冲。
- 作品星尘与关系网应扩展到较大视野，形成广阔星空，而不是集中在小圆盘内。
- 轨道线低对比显示，不可压过作品和主星。

首期重点作品可使用 Mock：

- 《静夜思》
- 《将进酒》
- 《望庐山瀑布》
- 《行路难》
- 《黄鹤楼送孟浩然之广陵》
- 《早发白帝城》

真实数据接入后：

- 重点作品由运营权重、知名度、数据完整度共同决定。
- 其余作品分批、分页或按空间分块加载。
- 不因真实作品数量增加而把所有标题一次性渲染到屏幕。

交互：

- 点击作品星体后，镜头连续靠近作品。
- 作品详情内容异步加载。
- 加载期间保留星体和空间背景，不切换成空白页面。
- 再次操作可返回李白作品星系。

### 8.8 阶段 7：作品放大与诗文详情

目标：完成从宏观宇宙到具体诗文的阅读落点。

要求：

- 作品详情至少展示标题、作者、朝代、体裁和正文。
- 正文来自结构化诗词库，不能依赖 WebGL 画面中的纹理文字。
- 简繁体以数据库权威文本为准。
- 诗文详情应保持现有诗云设计语言，可使用诗笺或半透明空间卡片。
- 详情出现时背景宇宙保持可感知，避免完全割裂。
- 关闭详情后返回原有空间位置和相机状态。

### 8.9 阶段 8：奇点坍缩与常规首页

目标：把文化宇宙的情绪落到用户自己的创作行为。

效果：

- 用户完成引导动作后，星体、轨道、关系线、诗文和粒子向一个奇点收拢。
- 坍缩过程中保持空间连续，不直接黑屏。
- 奇点在光影中融化，过渡到常规创作首页的古风背景。
- 常规首页在过渡结束时已经可交互。
- 不重复加载已经具备的用户额度、偏好和首页基础数据。

常规首页不因诗云宇宙改变核心业务结构，仍保留：

- 文字输入。
- 诗词类型选择。
- 体裁或词牌选择。
- 图片/视频素材上传。
- 今日创作额度。
- 开始创作按钮。

## 9. 镜头语言硬性要求

### 9.1 一镜到底

这是诗云宇宙的硬性验收条件。

- 全流程只使用一台主透视相机。
- 不创建第二台相机完成阶段切换。
- 不在用户点击后直接设置新的固定相机位置。
- 不在阶段开始或结束时重置相机 Quaternion。
- 不把 Camera、Target、Up 或 FOV 突然赋值为另一套预设。
- 每一段路径的起点等于上一段结束时旅行者的实际位置。
- 下一段镜头从上一帧真实 Camera、Target、Up 和 FOV 开始插值。
- 相机滚转必须克制，避免眩晕。
- 环境切换采用交叉淡化和连续采样方向，不用瞬间换天空盒。

### 9.2 镜头节奏

- 苏醒：慢，强调观看。
- 起航：由静到动。
- 穿越：速度感最强，但不依赖满屏放射线。
- 抵达：自然减速，给用户识别空间的时间。
- 选择节点：镜头先确认目标，再继续推进。
- 坍缩：从广域收束到一点，节奏可逐渐加快。

### 9.3 连贯性验收

逐帧检查每个阶段交界处：

- Camera Position 差值连续。
- Camera Quaternion 差值连续。
- Target 差值连续。
- Up 向量连续。
- FOV 连续。
- 曝光和 Bloom 连续。
- 主体尺寸连续。
- 尾迹自然衰减，不在停泊帧突然消失。
- 新旧节点通过渐隐、渐显或尺度生长交替。

## 10. 视觉设计语言

### 10.1 色彩

- 宇宙底色：接近墨黑的青黑色。
- 主品牌色：玉石绿。
- 唐朝与李白高光：鎏金、月白。
- 离子与深空辅助色：低饱和青蓝。
- 紫色只作为少量深空层次，不作为主色。

### 10.2 空间分层

必须同时存在：

1. 无限远层：暗空、遥远恒星、低频深空结构。
2. 远景层：朝代星团和大尺度气体云。
3. 中景层：诗人恒星、星尘、关系结构。
4. 近景层：用户诗光、彗星、诗文尾迹。
5. UI 层：品牌、章节文案、按钮和提示。

### 10.3 气态云

- 主要气态云使用 Shader、体积采样、粒子体积或真实三维网格实现。
- 气体边缘要有侵蚀、细丝和密度变化。
- 云体缓慢流动，运动速度低于旅行者。
- 相机穿入时自动降低近场密度，避免全屏漂白。
- 远看璀璨，进入后让出视觉主角。
- 不允许把设计稿整张星云图直接贴成固定背景并作为主要视觉。

### 10.4 恒星与作品

- 朝代：星团，不是普通节点球。
- 诗人：恒星，有色温、表面和日冕差异。
- 李白：高亮主恒星。
- 作品：围绕诗人运动的作品星体或卫星。
- 用户：能量水滴/诗光，具有方向感。
- 任何层级都不能统一使用“发光球 + 一圈光环”。

### 10.5 UI

- UI 保持安静，把主要视觉让给宇宙。
- 一屏只保留当前章节、简短叙事、主操作和必要手势提示。
- 不展示技术状态、坐标、FPS 或调试信息。
- 文案应具有叙事感，但不堆砌空泛口号。
- 品牌 Logo 使用项目真实素材，不临时拼接粗糙 slogan。

## 11. 交互要求

### 11.1 基础手势

- 单指拖动：360° 环顾。
- 双指缩放：在允许探索的停泊阶段调整远近。
- 点击恒星：选择朝代、诗人或作品。
- 点击主操作：继续当前引导路线。
- 点击关闭：退出作品详情并回到原相机状态。

### 11.2 引导与自由探索

- 引导飞行期间锁定手势，避免用户破坏镜头轨迹。
- 抵达停泊点后开放环顾和缩放。
- 用户点击继续后平滑收回控制权，再进入下一段航行。
- 不能在用户仍拖动时强行瞬间改变视角。

### 11.3 中断与恢复

建议：

- 页面进入后台时暂停动画时间线和高耗能 Shader。
- 返回前台后从当前阶段恢复，不从头自动重播。
- 内存不足或 WebGL Context Lost 时显示轻量降级页。
- 若拓扑接口失败，仍可使用已缓存的引导节点完成品牌体验。

## 12. 中华诗词库数据方案

### 12.1 数据来源

计划导入：

- `chinese-poetry/chinese-poetry`
- 后续经过确认的权威诗词、作者、词牌和韵律数据源

开源数据导入前必须核对：

- 仓库许可证。
- 单个数据文件的来源与版权说明。
- 是否允许商业使用、修改和再分发。
- 是否包含需要单独署名的数据。

### 12.2 是否需要预处理

必须预处理，不能直接把 GitHub JSON 原样提供给前端。

预处理至少包括：

- 统一朝代编码。
- 规范作者姓名、别名和异体字。
- 合并重复作者记录。
- 合并重复作品和版本。
- 保留简体、繁体和原始文本版本。
- 清理无效空格、错行、异常标点和乱码。
- 识别作品体裁、词牌、标题和正文。
- 建立作者与作品关系。
- 建立作品与题材、意象、地点、典故的可选关系。
- 为作者和作品计算稳定 ID。
- 计算作者知名度和作品推荐权重。
- 标记数据来源、原始文件和导入版本。
- 为拓扑计算预生成坐标和 LOD 层级。

### 12.3 数据库存储结论

已确认方向：

- 完整中华诗词库可以先存入现有 PostgreSQL/Supabase。
- 基础浏览、作者作品查询和拓扑加载不需要独立向量数据库。
- 诗词库与现有用户作品应使用独立业务表或独立 Schema，避免混用。
- 大型拓扑 JSON、纹理和模型不直接存 PostgreSQL，放入 COS/CDN。
- 对外拓扑可以由数据库预计算后生成版本化静态分块。

建议核心表：

```text
poetry_dynasties
poetry_authors
poetry_author_aliases
poetry_works
poetry_work_variants
poetry_work_lines
poetry_forms
poetry_tags
poetry_work_tags
poetry_sources
poetry_import_batches
poetry_universe_nodes
poetry_universe_edges
poetry_universe_tiles
```

### 12.4 是否需要向量数据库

首期不需要单独部署向量数据库。

适合使用 PostgreSQL 普通索引的场景：

- 按朝代查作者。
- 按作者查作品。
- 按作品 ID 查详情。
- 按词牌、体裁或标签筛选。
- 加载已经预计算的拓扑节点。

未来需要以下能力时再启用 pgvector：

- 语义搜索相似诗文。
- 按意象、情绪或自然语言探索宇宙。
- RAG 检索。
- 相似诗人或相似作品推荐。

即使启用向量能力，也优先使用 Supabase/PostgreSQL 的 pgvector，除非数据量、召回延迟或运维要求明确证明需要独立向量数据库。

### 12.5 拓扑预计算

不能在每次公共请求中实时计算全部诗人和作品坐标。

离线任务负责：

- 根据朝代、作者和作品关系生成分层拓扑。
- 为每个层级生成稳定三维坐标。
- 根据权重确定节点尺寸和默认可见性。
- 生成不同 LOD 的节点集合。
- 将大规模拓扑切成空间 Tile。
- 输出版本化、压缩后的 JSON 或二进制数据。
- 上传 COS/CDN。

同一数据版本下坐标必须稳定，避免用户每次进入时星体位置完全变化。

## 13. 拓扑接口设计

### 13.1 设计原则

- 初始请求小。
- 分层加载。
- 空间分块。
- 游标分页。
- 可长期缓存。
- 接口不返回 Shader、材质和具体渲染参数。
- 前端负责把业务节点映射为渲染视觉。
- 重点节点与普通星尘分开。

### 13.2 推荐接口

初始化：

```http
GET /v1/public/poetry-universe/bootstrap
```

返回：

- 当前宇宙数据版本。
- 朝代星团概要。
- 引导路线。
- 初始资源清单。
- 各质量档资源地址。

加载一个星团：

```http
GET /v1/public/poetry-universe/clusters/{clusterId}?lod=1
```

加载诗人恒星系：

```http
GET /v1/public/poetry-universe/authors/{authorId}/system?lod=1
```

分页加载作者作品：

```http
GET /v1/public/poetry-universe/authors/{authorId}/works?cursor=...&limit=50
```

加载空间分块：

```http
GET /v1/public/poetry-universe/tiles/{version}/{level}/{tileId}
```

加载作品详情：

```http
GET /v1/public/poetry-universe/works/{workId}
```

### 13.3 返回数据示例

```json
{
  "version": "2026-07-30.1",
  "nodes": [
    {
      "id": "author:li-bai",
      "kind": "AUTHOR",
      "name": "李白",
      "subtitle": "诗仙",
      "position": [-45, 21, -518],
      "importance": 1,
      "workCount": 1000,
      "featured": true
    }
  ],
  "edges": [
    {
      "source": "author:li-bai",
      "target": "work:quiet-night",
      "kind": "CREATED"
    }
  ],
  "nextCursor": null
}
```

颜色、Bloom、Shader Steps、粒子大小等不属于业务接口字段。接口可返回语义权重或推荐色温类别，但不能与某一版 Three.js 实现强绑定。

### 13.4 缓存

推荐：

- Bootstrap：短 TTL + ETag。
- 版本化 Tile：长缓存、Immutable。
- 作者作品列表：中长 TTL。
- 诗文详情：长 TTL + ETag。
- 版本更新通过新 URL 发布，不覆盖旧 Tile。
- 高频公共数据优先由 COS/CDN 返回，减少数据库连接压力。

## 14. 未登录访问、安全与防刷

### 14.1 业务结论

诗云宇宙展示的是公共文化数据，业务目标不是防止用户看到或抓取诗词，而是防止恶意流量拖垮 API、数据库和带宽。

### 14.2 防护措施

- 静态拓扑和资源走 CDN。
- API 使用网关限流。
- 结合 IP、Installation ID、User-Agent 和异常访问模式限流。
- 对 Bootstrap、Tile 和诗文详情设置不同限流规则。
- 开启 WAF、基础 DDoS 防护和 Bot 策略。
- 支持 ETag、304 和客户端缓存。
- 限制分页大小和最大翻页深度。
- 不提供无边界的“导出全部诗词”接口。
- 服务端不信任前端传入的拓扑版本、LOD 或 Cursor。
- 不在小程序或 H5 内放置数据库密钥、COS SecretId/SecretKey。

Installation ID 只能作为限流和体验恢复的辅助维度，不能当作不可伪造身份。对公开内容使用签名参数也不能真正阻止抓取，不应把复杂签名当作核心安全方案。

### 14.3 容量与查询性能

- 浏览查询必须命中明确索引。
- 首页不能跨表扫描全部作品。
- 作者作品数、推荐权重和拓扑坐标预计算。
- 复杂统计由离线任务生成。
- 高频拓扑不直接压到云 PostgreSQL。
- 数据库只负责事实数据和增量更新，CDN 负责大规模读取。

## 15. 前端技术方案

### 15.1 实现路径

当前确认：

1. 先使用独立 H5 原型验证视觉、镜头和性能。
2. 核心技术使用 Three.js + GLSL。
3. 原型通过后，优先评估小程序 WebView 承载。
4. 若 WebView 性能或交互存在不可接受问题，再评估小程序 Canvas/WebGL 适配。
5. 常规首页仍由原生小程序页面承载。

### 15.2 场景结构

```text
Scene
├── Infinite Background
│   ├── Dark Star CubeTexture
│   └── Background Star Field
├── Dynasty Clusters
│   ├── Tang Spiral Cluster
│   ├── Volumetric Gas
│   └── Distant Dynasty Nodes
├── Tang Poet Field
│   ├── Named Poet Stars
│   └── Minor Stars
├── Li Bai System
│   ├── Li Bai Main Star
│   ├── Work Orbits
│   ├── Work Dust
│   └── Fluorescent Relation Web
├── Traveler
│   ├── Energy Droplet
│   ├── Ion Trail
│   ├── Smoke Trail
│   └── Sparks
└── UI Overlay
```

### 15.3 渲染原则

- 大量恒星使用 `THREE.Points` 或 InstancedMesh。
- 气态云使用分档 Ray Marching、粒子体积或低模体积代理。
- 环境图使用压缩纹理。
- 模型使用 glTF/GLB；生产阶段评估 Draco/Meshopt。
- 纹理优先 WebP/KTX2。
- 粒子透明贴图控制尺寸并生成 Mipmap。
- Bloom 只增强高光，不用于掩盖主体建模不足。
- 不用大量 DOM 元素渲染每颗普通星。
- 只有当前可交互重点节点显示 DOM 标签。

### 15.4 分阶段加载

```text
初始：
  Logo + 暗空 + 用户诗光 + 远处唐朝星团

苏醒期间：
  预加载唐朝星团近景、彗星素材

驶向唐朝：
  预加载诗人恒星与标签

停泊诗人层：
  预加载李白星系拓扑

驶向李白：
  预加载重点作品与轨道

点击作品：
  请求具体诗文详情
```

不能在进入页面时一次性加载所有朝代、诗人和作品。

## 16. 设备适配与性能

### 16.1 质量分档

高档：

- 高像素比。
- 高粒子量。
- 多层体积云。
- 更高 Ray Marching Steps。
- 完整 Bloom 和关系线。

中档：

- 降低像素比。
- 减少粒子和云层。
- 保留完整叙事与主要视觉。

低档：

- 关闭或简化体积云。
- 使用预烘焙低分辨率远景。
- 减少关系线、诗文彗星和普通星尘。
- 保留唐朝、李白、重点作品和一镜到底。

不支持 WebGL：

- 显示静态品牌过渡图。
- 允许直接进入常规创作首页。

### 16.2 建议性能目标

- 首屏可见内容：Wi-Fi 下 1.5 秒内。
- 首次可交互：Wi-Fi 下 3 秒内，普通 4G 下 5 秒内。
- 高档设备：目标 50～60 FPS。
- 中档设备：目标不低于 35 FPS。
- 低档设备：目标不低于 25 FPS。
- 初始压缩资源：建议控制在 5 MB 内。
- 完整引导累计资源：建议控制在 18 MB 内。
- 页面切后台后停止高频渲染。
- 资源和材质必须及时 Dispose。

以上为验收目标，最终以微信真机测试结果校准。

### 16.3 无障碍与舒适度

- 尊重系统“减少动态效果”设置。
- 减少动态效果时缩短飞行并降低相机旋转和速度。
- 避免快速闪烁。
- 避免大幅频繁滚转。
- 文本颜色对比满足可读性。
- 关键操作具有明确可访问名称。

## 17. 素材与版权

### 17.1 原则

- 原型可以使用许可明确的高质量素材进行验证。
- 生产上线前必须确认每项素材允许商业使用。
- 不使用来源不明的星空图、模型和粒子包。
- 不以“网上下载”替代许可证审查。
- 生成式素材需保留生成记录和提示词版本。
- 静态素材必须达到实际展示分辨率，不得依赖放大低清图。

### 17.2 当前原型素材

- NASA Deep Star Maps：深空环境参考。
- NASA Bennu：彗星几何参考。
- Kenney Particle Pack：CC0 烟雾、耀斑和火花。
- `javaLuo/water`：仅作为非商业原型的镜头语言和本地参考素材。

`javaLuo/water` 的素材和实现不得未经重新确认直接用于商业上线版本。生产版本需要替换或取得明确授权。

## 19. 异常与降级

### 19.1 资源失败

- 单个次要纹理失败：使用默认粒子材质继续。
- 次要诗人节点失败：保留李白引导主线。
- 李白作品列表失败：使用内置重点作品 Mock 或本地缓存。
- 诗文详情失败：提示稍后重试，不退出宇宙。
- 关键 3D 场景失败：显示静态品牌过渡并进入常规首页。

### 19.2 性能不足

- 自动降低像素比。
- 减少体积云采样。
- 降低粒子数量。
- 关闭次要 Bloom。
- 降低关系线数量。
- 保留镜头、主星和重点作品。

### 19.3 页面中断

- 页面隐藏：暂停渲染和时间线。
- 页面恢复：从当前阶段继续。
- WebGL Context Lost：尝试一次恢复；失败后降级。
- 不因网络重试重复触发阶段或重复创建相机。

## 20. 验收标准

### 20.1 产品验收

- 首次进入无需登录即可完成体验。
- 用户能够理解自己是正在飞行的诗光。
- 用户能够从远处识别唐朝星团。
- 用户能够识别李白、杜甫和王维。
- 李白是诗人层最耀眼的恒星。
- 用户能看到作品围绕李白运行。
- 用户能点击作品查看诗文。
- 动效结束后进入常规创作首页。
- 再次进入规则符合体验版本记录。

### 20.2 视觉验收

- 实际互动过程中至少有一个关键帧达到已确认静态设计稿的主要视觉效果。
- 不是只有设计稿好看，真实场景中的分辨率、细节、光影和气体流动也必须成立。
- 远景有深邃暗空，中景有真实动态星云，近景有掠过物。
- 不出现低清天空盒、明显贴图接缝或静态云墙。
- 不出现“光球 + 粗光圈”的统一廉价造型。
- 用户诗光具有清晰水滴轮廓和自然尾迹。
- 诗文方向与彗星方向一致。
- 李白作品关系网具有广度、弯曲和层次。
- UI 不遮挡主星和核心交互。

### 20.3 镜头验收

- 全流程只有一台主相机。
- 所有阶段交界逐帧无跳变。
- 点击按钮不会突然切换摄像机角度。
- 环境切换无明显跳帧。
- 停泊与下一次起航连续。
- 李白星系停泊点不与李白主星重叠。
- 返回作品星系时恢复原相机状态。

### 20.4 性能验收

- 在目标 iPhone、主流 Android 和低端 Android 各完成一轮真机测试。
- 不出现持续内存上涨。
- 不出现大量 Shader 编译错误。
- 不出现 WebGL Context 高频丢失。
- 中低档设备触发正确质量降级。
- 资源加载失败不阻塞进入常规首页。

### 20.5 数据与接口验收

- 拓扑首包不包含全部诗文。
- 诗人作品支持分页。
- 作品详情按需加载。
- 公共接口不依赖登录。
- CDN 缓存和 ETag 生效。
- 数据版本可回滚。
- 相同版本节点坐标稳定。
- 简繁体和原文没有因渲染链路丢失。

## 22. 已确认与待确认事项

### 22.1 已确认

- 先做 H5 原型验证，再决定小程序最终承载方式。
- 采用 Three.js/GLSL。
- 用户是能量水滴/诗光，不是普通光球。
- 使用第三视角跟随和停泊后 360° 环顾。
- 全程一镜到底。
- 第一引导路线为唐朝—李白—李白作品。
- 星云气体必须动态存在于三维空间。
- 诗人是恒星，李白最亮。
- 作品围绕李白运行，并通过荧光关系网连接。
- 作品内容异步加载。
- 最后坍缩到常规创作首页。
- 首次体验不需要登录。
- 真实诗词数据需要预处理。
- 基础浏览先使用 PostgreSQL，不单独部署向量数据库。
- 主要拓扑通过预计算和 CDN 分发。
- 音乐不是首期必需项。

### 22.2 待确认

- 首次体验是否展示明确“跳过”按钮，以及出现时机。
- 完成体验后多久展示“再次进入诗云宇宙”入口。
- 首期除李白外是否开放第二位真实诗人星系。
- 真实诗词库最终采用的许可证和数据源组合。
- 诗人知名度、作品推荐权重的运营规则。
- 作品关系线首期只表达作者关系，还是加入意象/时间/地点关系。
- 小程序最终采用 WebView 还是原生 Canvas/WebGL。
- 生产素材是否全部自研，或采购部分商业模型和纹理。
- 首期最低支持的微信基础库、iOS 和 Android 版本。
